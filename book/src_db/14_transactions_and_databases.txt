# Transactions and databases
## Taking a change back
A transaction makes a group of changes that you can undo. `begin` starts it. `commit` keeps every change since `begin`. `rollback` throws them all away.
::: db
create table account with id integer primary key, owner text, balance integer
insert into account values (1, "Asha", 500), (2, "Ravi", 300)
begin
update account set balance = balance - 200 where id is 1
update account set balance = balance + 200 where id is 2
find * from account
rollback
find * from account
:::
After `rollback` the balances are what they were. With `commit` in its place, they would be kept.
::: db
begin
update account set balance = balance - 200 where id is 1
update account set balance = balance + 200 where id is 2
commit
find * from account
:::
A transaction covers the whole database: its tables, their rows, and its views. Anything inside it can be undone, including `create table` and `drop table`.
## A transaction that is never closed
If a script ends while a transaction is open, the engine rolls it back and says so, so that a forgotten `commit` never keeps half of a change.
::: db
begin
delete from account where id is 1
:::
::: db
find * from account
:::
Asha is still there. There are no savepoints, and there is no second writer: one script runs at a time.
## Databases
A database is a set of tables, saved as one file called `<name>.edb`. `create database` makes a new one and switches to it, and `use database` switches to one that exists.
::: db
show databases
create database shop
create table item with id, title
insert into item values (1, "Pen")
use database book
show tables
:::
`show databases` lists only the database that is open. The files of the others are in the folder, and `use database shop` opens `shop.edb`.
::: db
use database shop
find * from item
:::
## Removing a database
`drop database` deletes the database and its file, and needs `confirmed`.
::: err
drop database shop
:::
::: db
drop database shop confirmed
:::
