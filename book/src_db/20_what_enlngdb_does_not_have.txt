# What EnlngDB does not have
A list of what is missing is part of a reference. Each of these is something a statement or a program could be written for, and none of them exists. EnlngDB gives an error or a message when you try.
## Not there at all
- **Certificates.** A client trusts a server the first time by its fingerprint, as ssh does, and checks its key after that (chapter 14).
- **Rights on a file.** Users and rights are checked by the server. Anyone who can read the `.edb` file can read the data, unless the file is encrypted (chapter 14); then anyone with the password can.
- **Zone names.** Time zones are offsets from UTC such as `+05:30`; names such as `Asia/Kolkata` are not known.
- **Arrays and user types.** A column holds one value of one of the eight types; a list goes into a `json` column.
## There, but different from what you may expect
- **Indexes.** A `unique` index is a rule that is enforced. A plain `create index` is recorded and shown, and does not change anything else. The engine finds rows by `column is value`, `>`, `<`, `between`, `like` and `or` on its own where it pays (chapter 15); `not`, a `like` with fewer than three letters in a row, and a condition on a calculation read every row.
- **One program at a time, or the server.** A second program that opens a database in use waits up to 5 seconds and then stops with an error; many programs at once go through `enlngdb --serve`, which runs the requests that change something one at a time, and those that only read at the same time in reader processes (chapter 14).
- **Writing part of a file, always.** A script that changed rows writes only the change, to a log beside the file; the whole file is still written when the log passes a quarter of the file, when columns or tables change, and for an encrypted database. Rows are read only when needed, and lookups by a key, a unique column or a one-column index use the index kept in the file, and so do ranges and `like "abc%"` on those columns; `like "%abc%"`, and any condition on a column without a key, `unique` or an index, reads every row (chapter 15).
- **Counting and dates.** `datediff` counts days, `seconds_between` seconds; a moment with a zone is turned to UTC.
## Limits
4,096 tables in a database, 256 columns in a table, 512 columns in a result, 32 indexes on a table, 63 characters in a name. A statement and a text value can be as long as memory allows (chapter 17). Triggers set each other off up to 6 levels deep.
## Two engines, one language
EnlngDB also exists as a Python package for scripting. This book describes the C engine, `enlngdb.exe`, which is the one in the Enlangg toolchain, the playground and Studio on the Enlangg site. Features of the two engines are not the same, and a script that runs in one may not run in the other.
## Where to go next
- Run the scripts of this book yourself: copy a script into a file, run `enlngdb file.enlngdb`.
- Open the playground on the Enlangg site, pick the preset "Rules, Subqueries & Views", and change it.
- Read the tests in the repository, `tests/test_enlngdb_sql.py` and `tests/test_enlngdb_queries.py`: each one is a small script with the answer it must give.
