# Limits and Known Gaps in 5.5.1

A manual that only lists strengths is advertising. This chapter lists what toolchain 5.5.1 does not do, or does badly, with the evidence for each. Everything here was checked by running the program shown or the command named. If a later version fixes something, the change belongs in the release notes, not in a quiet edit of this page.

## Things that do not exist

| Claim you may have seen | Reality in 5.5.1 |
|---|---|
| Python interoperability | There is no way to call Python from Enlangg or the reverse. A file named `demo_enlngdb_python.py` in the examples folder is a Python script that talks to a database of its own. |
| Calling C libraries (FFI) | Not implemented. |
| Building an Android APK or iOS IPA | Not implemented. `enlngm build --target apk` prints "APK packaging not yet implemented." (chapter 32). |
| Threads and real parallelism | None. `lib_concurrency` models queues and locks in ordinary single-threaded code (chapter 29). |
| Network access | Nothing opens a connection. `lib_net` builds and reads text only (chapter 28). |
| Fetching packages | `enlangg pkg` links the eleven bundled library files. It does not download anything (chapter 33). |
| Slicing such as `text[0:3]` | Not in the language. Use `sub_string` from `lib_strings`, or a loop (chapters 24 and 35). |
| Nested assignment such as `grid[1][2] = 5` or `tasks[1]["done"] = true` | A syntax error. Pull the inner list or map into a name first, then assign through that name (chapter 38). |
| Counting down with `for i from 3 to 1 by -1` | The loop does not run. Count up and subtract. |
| A debugger | None in 5.5.1. `show` is the tool. |

## Behaviours that surprise people

These do work, but not the way a newcomer from another language would guess.

- **Whole numbers divide whole.** `7 divided by 2` is 3. Write one side as `7.0` for a fraction. Dividing by zero gives 0 instead of an error.
- **Numbers wrap.** Whole numbers are 64 bits. Past that they roll over silently. Factorials above 20 are the usual place this happens.
- **`ask` always gives text.** Convert with `parse_int` before doing arithmetic, or the `times` operator will repeat the text.
- **Names made by `ask` belong to their block.** Inside a loop, each pass makes a new one; the outer name is not updated.
- **Functions cannot see outer names.** Everything a function needs must be passed in. Maps and lists passed in are shared, so changes made through them are visible to the caller.
- **A zero-argument call needs parentheses.** `stack_size(s)` takes an argument; `create_stack()` takes none and must still be written with `()`.
- **`split` keeps empty pieces.** `split("a,,b", ",")` has three items, the middle one empty, and a separator is matched as a whole. This changed in 5.5.1; older releases dropped empty pieces.
- **Maps have no order.** Do not print a whole map and expect the keys in the order you typed them.
- **Some ordinary words are reserved.** `stop`, `times`, `from` and others cannot be names (chapter 40 lists them). A function written `function f with times:` fails to read with the message "Expected ':' before block". If you meet that message on a line that looks fine, check for a reserved word.

## Bugs that remain

These are faults in the toolchain or its library files, not in the way they are described here.

| Where | What happens |
|---|---|
| `lib_ds`: `lru_size` | Counts entries that were already forgotten. |
| `lib_net`: `parse_url` | Leaves a `#fragment` attached to the query. |
| `enlng emit-c` | The comment at the top of the generated C names an old version number. |
| `string_add`, `string_insert`, `string_replace` | Decide which argument is the text by comparing lengths; results are hard to predict. The book avoids them. |
| `enlngs` | Runs only a small part of the script language natively: `create`, `set`, `show`, `repeat`, `if`, `function`. Page-oriented lines are for the JavaScript translation. |
| `freeze` | Protects the name only. A frozen list can still be changed with `append`, and elements can still be assigned. |

## Fixed in 5.5.1

The first edition of this book listed these as faults of 5.5.0. They are fixed from 5.5.1, and the chapters mention each one where it applies.

| Was | Now |
|---|---|
| `freeze` did not stop a later assignment. | Assigning to a frozen name is an error when the file is read. |
| `split` dropped empty pieces and treated each character of the separator as a separator. | It keeps empty pieces and matches the separator as a whole, which also repairs `string_replace_all` and `string_format_1/2/3`. |
| `arrange` and `arrange_list` in `lib_std` could not be called. | They are named `arrange_text` and `arrange_items`. |
| `set_remove` left a `null` in the set. | It removes the item. |
| `file_word_count` counted only space-separated chunks. | A line break also ends a word. |
| `enlngs` did not calculate `total * 2` and wrote invalid JavaScript for `show "a" b`. | It has a real expression parser, and several values in one `show` work in both modes. |

## Platform limits

- The preview windows of `enlngf` and `enlngm` use Windows features. On Linux and macOS, `enlngf build`, `enlngd compile` and `enlngs compile` still work because they only write files.
- The installers are not code-signed, so Windows SmartScreen or macOS Gatekeeper may warn you the first time you run them (chapter 2).
- Programs run through the built-in interpreter by default. For compute-heavy programs, `enlng run --native` or `enlng build` compile through a C compiler if one is installed. If none is, the tool says so and `enlng run` still works.

## Speed

The numbers on the Enlangg website come from one Windows machine and one small program: starting and printing "hello" took about 12 milliseconds, against about 73 for a Python script doing the same. That says something about start-up time and nothing about speed on large problems. The built-in interpreter is an ordinary interpreter. If you have a heavy calculation, expect it to be slower than compiled C and probably slower than Python's optimised libraries. Measure your own program before you decide.

## How to report a problem

If a program in this book behaves differently on your machine, check `enlng --version` first. The outputs here were produced with 5.5.1. If the version matches and the output differs, that is worth reporting at the project's GitHub page, with the program and its output.
