# enlngs and enlngm: Scripts and Mobile Previews

## enlngs: page scripts

`enlngs` runs small scripts in a syntax close to Enlangg's, and can translate them into JavaScript for a web page. Its main use is making an `.enlngf` page respond to clicks and timers.

::: sh
enlngs <file.enlngs>                       run a script
enlngs -e "<statement>"                    run one statement
enlngs compile <file.enlngs> [-o out.js]   write JavaScript
:::

A simple statement runs directly:

::: cmd
enlngs -e "show 2 + 3"
:::

### A script file

A script keeps its data in names made with `create`, changes them with `set`, and prints with `show`:

::: cmd
@@ count.enlngs
create total as 0
create name as "Asha"
set total = total + 5
show "total is " + total
show name
@@@
enlngs count.enlngs
:::

### Calculating and showing several values

Expressions use the usual precedence: multiplication and division bind tighter than addition and subtraction, and brackets override both. The operators can be symbols or words (`times`, `divided by`, `mod`, `plus`, `minus`, `is greater than`, `and`, `or`):

::: cmd
@@ calc.enlngs
create total as 5
show total * 2
show 2 + 3 * 4
show (2 + 3) * 4
show 10 - 3 - 2
show 7 / 2
show total times 3 plus 1
show total is greater than 3 and total is less than 9
@@@
enlngs calc.enlngs
:::

`show` accepts several values in a row and prints them with a space between, the way `show` does in Enlangg:

::: cmd
@@ many.enlngs
create total as 5
create name as "Asha"
show "total is" total
show name total * 2 "end"
@@@
enlngs many.enlngs
enlngs compile many.enlngs -o many.js
tail -n 2 many.js
:::

The JavaScript that `compile` writes passes the values to `console.log` as separate arguments, so it is valid JavaScript and prints the same thing. Division is true division, as in JavaScript: 7 divided by 2 is 3.5, and dividing by zero gives `Infinity`.

In 5.5.0 this was different. The tool printed `total * 2` as text instead of 10, and `show "total is" total` became `console.log("total is" total)`, which is not valid JavaScript.

### Blocks and indentation

A line ending in a colon owns the lines indented under it. `repeat`, `if` with an optional `else:`, and `function` run natively:

::: cmd
@@ loop.enlngs
in script:
    create total as 0
    repeat 3 times:
        set total = total + 2
        if total > 3:
            show "big" total
        else:
            show "small" total
    show "done" total
@@@
enlngs loop.enlngs
:::

Blocks that describe a web page, such as `every 1 second:`, `after 3 seconds:` and `fetch data from ...:`, have nothing to act on in a terminal. The tool skips them and the lines under them when you run a script, and translates them to JavaScript when you compile.

### Scripts written for pages

The `to do` blocks, `every 1 second:` timers and `set text of "id" to ...` lines in the larger example scripts are meant for pages: they describe what happens in a browser. Compiling them to JavaScript is the intended use; running them in the terminal skips them.

## enlngm: mobile app previews

An `.enlngm` file describes a phone app: screens, bars, buttons, themes. `enlngm` shows it in a window the size of a phone (390 by 844) and can export it as C source for that preview window.

::: sh
enlngm <file.enlngm>                  open the preview window
enlngm export <file.enlngm> -o x.c    export the preview as C source
enlngm build <file.enlngm> --target apk
:::

The preview window is a Windows feature and needs a screen, so this book does not show its output. Exporting does not need a screen:

::: cmd
@@ app.enlngm
mobile app "Counter":
    screen "Home":
        text "Hello"
@@@
enlngm export app.enlngm -o app.c
:::

### Building an APK or IPA

The `build` command accepts `--target apk` and `--target ipa`. In toolchain 5.5.1 it does not produce either. This is what it says:

::: cmd
@@ app.enlngm
mobile app "Counter":
    screen "Home":
        text "Hello"
@@@
enlngm build app.enlngm --target apk -o app.apk
:::

So you cannot make an installable phone app with this version. The preview window is the working part. Anything you read elsewhere that says otherwise describes a plan, not a feature.
