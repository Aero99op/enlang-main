Chapter 1: Sovereign Grammar & Spoken Syntax

Enlangg is engineered upon the fundamental premise that computation should be expressible in natural, phonological English without relying on 1960s mechanical teletype symbols (semicolons, braces, arrow operators, or bitwise glyphs).

The Sovereign Grammar Invariant

Every spoken keyword in Enlangg resolves to an unambiguous lexical token. Punctuation is never mandatory for statement termination; whitespace and line indentation form the clause hierarchy.

Spoken Arithmetic & Variable Declaration

Variables are declared and assigned using the idiomatic set <identifier> to <expression> syntax. Mathematical operators are expressed as natural English phrases:

basic_math.enlng
type enlng freeze principal as 5000 freeze rate as 0.05 remember years as 3 remember interest as principal times rate times years remember total as principal plus interest show "Calculated Total Balance: $" total

Arithmetic & Assignment Operators

Spoken English Syntax Traditional Equivalent Example Expression Output Result
plus + set sum to 10 plus 25 35
minus - set diff to 100 minus 42 58
multiplied by * set area to width multiplied by height Area value
divided by / set avg to total divided by count Floating-point quotient
modulo % set rem to count modulo 2 Remainder
set ... to ... = set count to count plus 1 Mutates variable slot

Natural English Synonyms & Keyword Flexibility

Because English is a living, spoken human language, people naturally express ideas in synonyms. Enlangg embraces this fluidity: while set <id> to <val> is our primary idiomatic standard, the compiler natively accepts equivalent spoken alternatives with zero performance cost:

Operation / Intent Canonical Standard (Recommended) Spoken Synonyms (Permitted) Compiler Action
Variable Declaration set x to 10 let x = 10 · create x as 10 · declare x to 10 · initialize x to 10 Allocates stack slot & binds value
Variable Mutation set x to 20 update x to 20 · assign x to 20 · change x to 20 Overwrites slot in-place
Increment / Decrement increase x by 1 decrease x by 1 · set x to x plus 1 In-place arithmetic register update
Standard Output display "Hello" show "Hello" · output "Hello" · print "Hello" Flushes tokens to stdout
User Input ask "Enter name: " input "..." · read from user with "..." Stdin capture with type coercion
Collection Loops for each item in items: for every item in items: · for all item in items: Zero-allocation iterator traversal
Conditional Branching if x is greater than 10: if x > 10: · otherwise if ... · otherwise: Deterministic jump branch

The Universal 4-Way Access Engine (Dot-Free & Bracket-Free)

In traditional programming languages, accessing properties requires dots (obj.prop) and collections require brackets (arr[0]). Enlangg introduces Universal 4-Way Access Orthogonality: you can access any field, map key, or list index using pure conversational English or traditional notations interchangeably:

Access Form Syntax Example Spoken Intent Equivalent In Traditional PLs
1. Pure English 'of' status of card Property of object (zero dots, zero brackets) card.status
2. Pure English 'at' items at 0 · account at "balance" Container indexed at position or key items[0] · account["balance"]
3. Dot Notation card.status · account.tier Standard object member access card.status
4. Index Bracket items[0] · account["balance"] Standard subscript indexing items[0]
How does Enlng parse 'status of card'?

In the statement when status of card is "ACTIVE":, the Enlng lexer and parser recognize status as the property identifier, of as the universal relational preposition, and card as the target container in scope. This enables natural English reading order without ambiguity!

Chapter 3: Values, Lists and Maps

A program holds numbers, text, true/false values, lists and maps. You never allocate or free anything yourself: names are declared with remember, and the runtime keeps their values.

One Runtime, Two Ways to Run

enlng run executes your program with a built-in interpreter. enlng build and enlng run --native translate it to C and compile it with gcc. Both use the same value model (src/enlng_runtime.h), and our CI runs the same test programs through both and compares the output. One known difference: the C path prints decimal literals with six places.

Scopes follow the blocks you write: a name declared inside a loop or function is not visible outside it, and a function cannot see its caller's names. Runaway recursion stops with a clear runtime error instead of crashing.

Chapter 4: Spoken Control Flow

Branching and loops in Enlangg replace cryptic operators like ===, !=, &&, and || with spoken comparison clauses:

Spoken English Clause Equivalent Symbol Description
is equal to == Evaluates if operands have identical slot values
is not equal to != Evaluates if operands differ
is greater than > Strict greater-than numerical comparison
is less than or equal to <= Lower-bound comparison
otherwise / else else Fallback branch when condition evaluates false
while ... : while () {} Executes block as long as condition holds true
repeat N times: for (int i=0; i<N; i++) Bounded loop with zero loop counter overhead
control_flow.enlng
type enlng remember score as 94 when score is at least 90: show "Grade: Sovereign Tier A" otherwise: when score is at least 75: show "Grade: Tier B" otherwise: show "Grade: Tier C" remember counter as 1 repeat while counter <= 5: show "Iteration:" counter counter increases by 1

Chapter 5: Procedures, Functions & Error Safety

Reusable logic is encapsulated in procedures. Procedures can declare parameters, specify return types, and safely trap runtime errors with catch failure:

procedures_and_errors.enlng
type enlng # Function Declaration with 'with' and 'give' function calculate_mortgage with principal, rate, term_years: when principal <= 0: give 0.0 remember monthly_rate as rate divided by 12.0 remember months as term_years times 12.0 give principal times monthly_rate # Function Invocation using pure English 'with' (Zero Parentheses!) remember monthly as calculate_mortgage with 250000, 0.045, 30 show "Monthly Payment: $" monthly

Chapter 6: Building an Executable and Reading the C

With a C compiler installed you can turn any program into a standalone executable, or just look at the C that Enlangg generates:

terminal
enlng build hello.enlng -o hello # translate to C, build with gcc enlng emit-c hello.enlng # print the generated C99 source enlng run --native hello.enlng # build and run through gcc

Calling arbitrary C libraries from Enlangg code (a foreign function interface) is not available yet.

Chapter 8: EnlngDB Database Engine

EnlngDB is a database engine written in C. It is available as the standalone enlngdb.exe (about 106 KB) and through enlangg db. You write statements in English instead of SQL, and the data is saved to a file.

About Speed

An earlier version of this page listed per-operation timings against other database runtimes. Those figures were not backed by a published benchmark, so they have been removed. We will add numbers here once a reproducible benchmark is in the repository.

Natural Conversational DDL & DML Syntax

EnlngDB uses natural human phrasing for schema declarations, data insertions, query filtering, and in-table row/column updates:

university_scholars.enlngdb
type enlngdb; use university_db; create table scholars with id, name, cgpa, status; insert record into scholars with id 1, name "aryan", cgpa 8.2, status "probation"; insert record into scholars with id 2, name "meera", cgpa 9.4, status "honors"; insert record into scholars with id 3, name "kunal", cgpa 7.8, status "probation"; find all records from scholars; # 1. Conversational row update by condition in scholars change cgpa to 9.8 where name is "aryan"; # 2. Update with 'update' keyword & relational expression in scholars update status to "dean_list" where cgpa is greater than 9.0; # 3. Multi-field update in a single atomic instruction in scholars set cgpa to 9.95, status to "gold_medalist" where name is "aryan"; # 4. Bulk column update across all rows (unconstrained) in scholars set status to "active_enrolled"; find all records from scholars;

In-Table Mutation Grammar Reference

Syntax Pattern Example Phrase Behavior
in <tbl> change <col> to <val> where ...; in scholars change cgpa to 9.8 where name is "aryan"; Updates single column for matching rows
in <tbl> update <col> to <val> where ...; in scholars update status to "honors" where cgpa >= 9.0; Updates matching records using relational condition
in <tbl> set <col1> to <val1>, <col2> to <val2> where ...; in scholars set cgpa to 9.95, status to "topper" where name is "aryan"; Atomically updates multiple fields simultaneously
update <tbl> set <col> = <val> where ...; update scholars set status = "dean_list" where cgpa > 9.0; Standard SQL/DSL assignment phrasing
in <tbl> set <col> to <val>; in scholars set status to "active_enrolled"; Unconstrained column mutation across every row in table

Compiler Command Line Reference

The language tool is enlng; enlangg is a front door that picks the right tool for a file. Run enlangg --help for the full list of commands in your version.

Command / Flag Arguments Description
enlangg compile <file.enlng> [-o <out.exe>] Translates the program to C and builds a standalone executable with gcc (needs a C compiler)
enlangg emit-c <file.enlng> [-o <out.c>] Prints the generated C99 source
enlangg run <file.ext> [args...] Runs any Enlangg file with the right tool (.enlng, .enlngdb, .enlngs, .enlngf, .enlngd, .enlngm). .enlng files use the built-in interpreter, so no C compiler is needed
enlangg db <script.enlngdb> - Runs a database script with the native C engine
enlangg db -e "<query>" "<conversational query>" Runs one inline database statement
enlangg s <logic.enlngs> [-e "<script>"] Runs a script with the enlngs tool; no Python or Node.js needed
enlangg f <app.enlngf> [--port 3000] Opens a window (Windows only), or serves the page locally with f serve
enlangg d <theme.enlngd> [-o <out.css>] Inspects design tokens, or exports them as CSS with d compile
enlangg m <app.enlngm> [--target apk|ipa] Phone-sized preview window (Windows only). APK/IPA packaging is not implemented yet
enlngdb <script.enlngdb> - Native C database engine with data saved to a file
enlngs <logic.enlngs> [-o <out.js>] Script tool that generates JavaScript
enlngf <app.enlngf> serve / build Frontend tool: preview window (Windows), local server, and HTML build
enlngd <theme.enlngd> inspect / compile Design-token inspector and CSS generator
enlngm <app.enlngm> run / build / export Mobile screen preview (Windows)
enlng --version - Prints the tool version

Compiler Diagnostic Error Codes

Enlangg diagnostics deliver clear, actionable natural English error messages with exact line and token coordinates:

Code Error Name Root Cause Resolution
E001 UnresolvedSlotIdentifier Variable referenced before create instantiation Declare with create <id> of ...
E002 ClauseGrammarMismatch Invalid spoken phrasing or unrecognized operator clause Use standard tokens like plus, is equal to
E003 TypeCoercionFault Illegal operation between incompatible slot data types Ensure numerical or string parity before arithmetic
E004 DomainExtensionViolation Using UI DOM clauses in a backend .enlng file Move UI code into dedicated .enlngf domain
E005 ForeignABISymbolNotFound C library function not found in dynamic linker path Ensure shared library is installed in system PATH

The Grand Mastercode: Enterprise Core Banking & Fraud Ledger

Below is the complete, production-grade monolithic system written entirely in authentic Sovereign Enlng. It demonstrates every sovereign rule in harmony: immutable bindings (freeze), mutable memory (remember), the Universal 4-Way Access Engine (status of account, primary_account.tier, primary_account["balance"]), pure English functions with with and give, zero-parentheses functional invocations, in-place mutation (increases by, decreases by), recursive actuarial yield calculations, and Spatial Pair Sorting with silent words (the left of the pair is greater than the right of the pair: swap pair):

master_enterprise_system.enlng (187 Lines Monolithic Pure Enlng)
type enlng # ============================================================================== # 👑 ENLNG SOVEREIGN ENTERPRISE FINTECH ENGINE & REAL-TIME LEDGER # Monolithic Mastercode Demonstrating 100% True Authentic Enlng Grammar # Zero Cryptic Symbols • Universal 4-Way Access • Zero-Parentheses Invocations # ============================================================================== # Global System Constants freeze INSTITUTION_NAME as "Sovereign Reserve Bank" freeze PROTOCOL_VERSION as "2.0-SOVEREIGN" freeze BASE_CURRENCY as "USD" freeze MAX_TRANSACTION_LIMIT as 50000.0 show "==========================================================================" show "🏛️ " INSTITUTION_NAME "// ENTERPRISE LEDGER CORE (" PROTOCOL_VERSION ")" show "==========================================================================" # ------------------------------------------------------------------------------ # 1. FUNCTION DEFINITIONS (PURE ENGLISH, WITH PREPOSITION & GIVE) # ------------------------------------------------------------------------------ # Function with two parameters, zero parentheses, returning calculation via 'give' function compute_risk_score with amount, customer_tier: remember base_risk as 10.0 when customer_tier is "VIP": base_risk = 2.0 otherwise: when customer_tier is "CORPORATE": base_risk = 5.0 otherwise: base_risk = 15.0 when amount > 25000.0: base_risk increases by 25.0 otherwise: when amount > 10000.0: base_risk increases by 10.0 give base_risk # Function verifying card & account authorization function verify_transaction_status with account, tx_amount: # 4-Way Universal Access in action: 'property of object' remember card_status as status of account remember current_balance as balance of account when card_status is not "ACTIVE": give "REJECTED_CARD_INACTIVE" when tx_amount > current_balance: give "REJECTED_INSUFFICIENT_FUNDS" freeze limit as 50000.0 when tx_amount > limit: give "REJECTED_LIMIT_EXCEEDED" give "APPROVED" # ------------------------------------------------------------------------------ # 2. STATE INITIALIZATION (REMEMBER, LISTS, MAPS & OF/AT ACCESS) # ------------------------------------------------------------------------------ # Customer accounts represented as first-class composite maps remember primary_account as { "account_number": "ACT-908124", "holder_name": "Aero Henderson", "tier": "VIP", "balance": 85000.0, "status": "ACTIVE", "total_tx_count": 0 } remember merchant_account as { "account_number": "MER-441029", "holder_name": "Sovereign Cloud Data Center", "tier": "CORPORATE", "balance": 120000.0, "status": "ACTIVE", "total_tx_count": 0 } # Transaction batches as dynamic collections remember pending_transfers as [ {"id": "TX-101", "amount": 4500.0, "vendor": "Server Compute Cluster"}, {"id": "TX-102", "amount": 18200.0, "vendor": "Hardware Satellite Uplink"}, {"id": "TX-103", "amount": 1250.0, "vendor": "Edge Bandwidth Router"}, {"id": "TX-104", "amount": 32000.0, "vendor": "Quantum Core Accelerator"}, {"id": "TX-105", "amount": 800.0, "vendor": "Domain Registrar Service"} ] remember ledger_history as [] show "" show ">> Initializing System State..." show "Primary Account:" holder_name of primary_account show "Tier:" primary_account.tier show "Opening Balance: $" primary_account["balance"] show "Pending Transaction Batch Count:" count of pending_transfers show "" # ------------------------------------------------------------------------------ # 3. TRANSACTION PROCESSING PIPELINE (LOOPS, ACCESS & MUTATION) # ------------------------------------------------------------------------------ show ">> Executing Real-Time Transaction Verification Pipeline:" show "--------------------------------------------------------------------------" for tx in pending_transfers: remember tx_id as tx.id remember tx_amount as tx["amount"] remember tx_vendor as vendor of tx # Function invocation using pure English 'with' (zero parentheses!) remember auth_code as verify_transaction_status with primary_account, tx_amount remember risk as compute_risk_score with tx_amount, tier of primary_account when auth_code is "APPROVED": # Mutate account balance and counters using natural keywords balance of primary_account decreases by tx_amount total_tx_count of primary_account increases by 1 balance of merchant_account increases by tx_amount total_tx_count of merchant_account increases by 1 # Build settled audit receipt remember receipt as { "id": tx_id, "amount": tx_amount, "vendor": tx_vendor, "risk_score": risk, "status": "SETTLED" } append(ledger_history, receipt) show " [SETTLED]" tx_id "-> $" tx_amount "to" tx_vendor "(Risk:" risk ")" otherwise: show " [DECLINED]" tx_id "-> Reason:" auth_code show "--------------------------------------------------------------------------" show "Settled Ledger Records:" count of ledger_history show "Updated Primary Balance: $" primary_account.balance show "Updated Merchant Balance: $" merchant_account.balance show "" # ------------------------------------------------------------------------------ # 4. SPATIAL PAIR SORTING WITH SILENT WORDS (THE / IT IS) # ------------------------------------------------------------------------------ remember settled_amounts as [18200.0, 4500.0, 1250.0, 32000.0, 800.0] show ">> Sorting Settled Ledger Amounts via Spatial Pair Primitives:" show " Before Sorting:" settled_amounts repeat until sorted: for each pair in settled_amounts: when the left of the pair is greater than the right of the pair: swap pair show ">> After Spatial Sort (Ascending):" settled_amounts # ------------------------------------------------------------------------------ # 5. AGGREGATE SUMMARY AUDIT (REPEAT WHILE & RECURSION) # ------------------------------------------------------------------------------ function calculate_compound_yield with principal, rate, periods: when periods <= 0: give principal remember next_principal as principal + (principal times rate) give calculate_compound_yield with next_principal, rate, periods - 1 remember projected_yield as calculate_compound_yield with balance of primary_account, 0.05, 3 show "" show "==========================================================================" show "📊 FINANCIAL AUDIT SUMMARY & ACTUARIAL PROJECTIONS" show "==========================================================================" show "Account Number :" primary_account.account_number show "Account Status :" status of primary_account show "Closing Vault Balance : $" primary_account.balance show "Total Debits Processed:" total_tx_count of primary_account show "Projected 3-Yr Yield : $" projected_yield show "==========================================================================" show "👑 ALL SOVEREIGN ENLNG ENTERPRISE GRAMMAR RULES VERIFIED WITH EXIT CODE 0!" show "=========================================================================="
