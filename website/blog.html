Enlangg Release Notes

What changed in each release, and what is still missing.

Release Toolchain 5.5.0

enlng run now works without a C compiler

Until 5.5.0, enlng run translated your program to C and called gcc, so you needed a C compiler installed just to run a hello-world. The tool now includes a built-in interpreter, and enlng run uses it by default. Programs run the same way, with the same error messages, and nothing else has to be installed.

The C path is still there. enlng build hello.enlng -o hello and enlng run --native hello.enlng translate to C and compile with gcc, which is useful for a standalone executable. Both paths share one runtime, and our CI runs the same test programs through both and compares the output. One known difference: the C path prints decimal literals with six places.

terminal
enlng run hello.enlng # built-in interpreter, no gcc needed enlng run --native hello.enlng # via C and gcc enlng build hello.enlng -o hello # standalone executable (needs gcc)
Release Toolchain 5.4.2

An installer for Linux and macOS

Windows has had a graphical installer for a while. Linux and macOS now have enlangg-install.sh, a single self-extracting file with all seven tools for Linux x86_64, Linux aarch64 and macOS. It verifies its contents with SHA-256, installs under ~/.enlangg without root, adds that folder to your shell profile between marked lines, and writes an uninstaller that removes only what it installed.

Run it with sh enlangg-install.sh. It is not signed, so check the SHA-256 on the install page. The Windows installer is not signed either, and Windows SmartScreen may warn before you run it.

Roadmap Status

What is not built yet

Plain statements about gaps, so you do not have to find them yourself:

  • Calling Python packages and C libraries from Enlangg code is planned, not implemented.
  • Building APK or IPA packages from .enlngm files is not implemented. enlngm gives a phone-sized preview window on Windows.
  • The preview windows of enlngf and enlngm are Windows-only. enlngf serve and enlngf build work on every platform.
  • enlngf, enlngd and enlngs are native programs, but what they produce is HTML, CSS and JavaScript, not machine code.
