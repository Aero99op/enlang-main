Enlangg is a programming language written in plain English, with a toolchain of seven small native programs written in C. enlng run runs your code with a built-in interpreter, so no C compiler is needed. Six separate file types cover logic, UI, styling, scripts, mobile and databases.

Knowledge Base

Frequently Asked Questions

Key architectural concepts behind Enlangg's natural English compiler and runtime.

A fixed grammar parser turns each English sentence, such as remember count as 0, into a syntax tree. enlng run walks that tree with a built-in interpreter. enlng build translates the same tree to C and lets gcc produce an executable. Both paths share one runtime and are checked against each other in CI.

Domain isolation prevents architectural contamination. Core logic (.enlng), frontend components (.enlngf), server endpoints (.enlngs), design tokens (.enlngd), mobile screens (.enlngm), and database queries (.enlngdb) each have their own grammar and their own tool, so a database word cannot silently end up in a UI file.

Not to run programs. The installer puts seven small native tools on your machine (about 586 KB in total) and needs no admin rights. A C compiler such as gcc is only needed for enlng build or enlng run --native.

The tools are small native programs with nothing to load first. On one Windows machine with release 5.5.0, enlng run on a hello-world file took about 12 ms against about 73 ms for python hello.py (median of 30 runs). That is start-up time only; the interpreter is not tuned for heavy loops, which run faster with --native.
